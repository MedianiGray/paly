## 唯一的规矩：名字即承诺

一个项目只做一件事，**名字说什么，就只做什么**。

判定的方法很笨，但很好用：

1. 用一句话把它叫什么说清楚，比如"打砖块"。
2. 再问：它需要做第二件事吗？比如打砖块要不要带背包、带商店、带每日签到？
3. 如果需要——**不要塞进去**，另开一个项目，让它自己有个名字。

理由很实际：一个东西叫 A 却干着 B 的活，用户点进来会觉得被骗；维护的人也会慢慢搞不清它到底该管什么。项目越小，名字越准，越好活。

所以这里的每个页面都有一行"目标"，写在界面最上面。看完那行，你就该知道这局要干什么，不该期待别的。

## 加一个新项目

1. **先起名字。** 名字必须是玩家一看就知道要干什么的那种。"贪吃蛇"行，"神经突触共振模拟器"不行。
2. **写清它只做什么。** 一句话。写不出来，说明还没想清楚，先别写代码。
3. **对着 `PLAN.md` 的"不做清单"自查。** 把页面上能做的动作列一遍，除了名字承诺的那一个，多出来的每个动词都砍掉，或者另开项目。
4. **建一个单文件。** 放在 `games/<名字>.html`，CSS 和 JS 全写在里面。不引外部 CDN，不引框架，不联网取资源。
5. **自己存记录。** 最高分、最佳步数之类，用 `localStorage`，键名一律以 `paly.` 开头，例如 `paly.snake.best`，避免和别的项目撞。
6. **加一条返回入口。** 页面顶部放 `<a href="../index.html">← 返回</a>`。
7. **进门户。** 在 `index.html` 的 `.grid` 里复制一张卡片，改编号、标签、名字、描述，以及那行"目标"。
8. **手机上过一遍。** 至少确认：竖屏能玩、按钮点得到、不会误触缩放。
9. 提交，等 Pages 自动更新（推送到 `main` 后一两分钟）。

### 技术约定

- 单文件 HTML，样式与脚本内联。唯一的例外是门户自己的 `assets/portal.css` / `assets/portal.js`。
- 不用构建工具，不改目录结构，不加 `package.json`。
- 深色底 `#0b0e11`，强调色青 `#35e0c8`、琥珀 `#ffb347`。
- 尊重 `prefers-reduced-motion`：该关的动画就关掉。
- 数据不出浏览器：不发请求，不打点，不接第三方统计。

## 本地跑

直接双击 `index.html` 就能玩。想用本地服务器（推荐，路径行为与线上一致）：

```bash
python -m http.server 8765
# 打开 http://localhost:8765/
```

## 部署

仓库 Settings → Pages → Source 选 `Deploy from a branch`，分支 `main`，目录 `/ (root)`。

根目录的 `.nojekyll` 是给 Pages 看的：告诉它别拿 Jekyll 处理这些文件，省掉一类莫名其妙的 404。
